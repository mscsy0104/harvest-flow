- Claude Code는 컨텍스트 관리와 작업 제어를 통해 코드 작성을 더욱 효율적으로 진행할 수 있도록 지원합니다.
- Claude Code의 활용 방법에 대한 실제적인 가이드와 핵심 키워드를 제공하는 본문입니다.

# 데이터 #AI #코딩

---

### 본문
Anthropic의 Claude Code는 터미널 환경에서 직접 코드베이스를 읽고 수정하는 강력한 CLI(명령줄 인터페이스) 에이전트임. 하지만 이 도구를 100% 활용하려면 단순히 코드를 짜달라고 부탁하는 것을 넘어, 컨텍스트(문맥) 관리와 작업 제어가 필수적임.

---

# 1. 계획 먼저, 코딩은 나중에 (Plan Mode)

거대한 기능을 한 번에 만들어 달라고 하면 중간에 엉뚱한 방향으로 빠지기 쉬움. 코드를 바로 작성하게 하기보다 계획을 먼저 검토하는 것이 좋음.

* Plan Mode 활용: `Shift + Tab`을 눌러 모드를 전환하자. Claude에게 "먼저 어떻게 수정할지 계획을 브리핑해 줘"라고 한 뒤, 내용이 맞으면 구현을 승인하는 방식이 훨씬 안전함.
* 작업 분할: "기능 전체 구현" 대신, "스키마 먼저 작성 -> 마이그레이션 -> 엔드포인트 생성 -> 테스트 코드" 순으로 단계를 쪼개서 지시하자.
* (사견) 나는 보통 ① 원하는 방향을 주고, ② 방향에 대한 자세한 답변을 가지고, ③ 에이전트와 함께 좀 더 탄탄한 계획을 세우는 순으로 작업한다. 즉 질의응답을 진행한 후, 계획을 같이 세운다.

# 2. 적극적인 컨텍스트(기억) 관리

Claude Code는 대화가 길어질수록 컨텍스트 윈도우가 가득 차서 속도가 느려지고 성능이 떨어짐.

* `/compact` 명령어: 세션이 길어지면 수시로 `/compact`를 입력해 이전 대화의 불필요한 기록을 압축하자.
* `/clear`로 초기화: 완전히 새로운 기능이나 버그를 잡기 시작할 때는 과감하게 `/clear`를 입력하거나 새로운 세션을 여는 것이 토큰과 시간을 아끼는 길임.

# 3. `CLAUDE.md`를 프로젝트의 뇌로 만들기

매번 "우리는 TypeScript를 쓰고, 테스트는 Jest로 돌리며, 따옴표는 쌍따옴표를 쓴다"고 설명할 필요가 없음.

* 프로젝트 루트에 `CLAUDE.md` 파일을 생성하자.
* Claude는 폴더를 읽을 때 이 파일을 자동으로 로드함. 여기에 프로젝트의 코딩 컨벤션, 아키텍처 규칙, 빌드/테스트 명령어 등을 적어두면 알아서 규칙을 따름. (자주 틀리는 부분을 이 문서에 계속 업데이트하자.)

# 4. Claude가 스스로 검증하게 만들기

직접 코드를 실행하고 테스트하며 에러를 고치는 과정을 Claude에게 위임하자.

* 프롬프트 예시: "코드 작성 후 `npm run test`를 실행해서 통과하는지 결과를 직접 확인해 줘."
* MCP(Model Context Protocol) 서버 연동: `/mcp` 명령어를 통해 GitHub CLI를 연동해 PR을 직접 올리게 하거나, 로컬 데이터베이스에 접근해 데이터 스키마를 직접 조회하게 만들면 작업 효율이 극대화됨.

# 5. 알아두면 좋은 터미널 단축키 & 팁

* 실행 중지: Claude가 엉뚱한 코드를 짜고 있다면 `Ctrl + C` 대신 `Esc`를 누르세요. `Ctrl+C`는 프로그램 전체를 종료하지만, `Esc`는 현재 작업만 깔끔하게 중단시킴.
* 에러 로그 전달: 에러를 대충 요약해서 말하지 말고, 에러 스택 트레이스 전체나 로그를 그대로 복사해서 터미널(`Ctrl + V`)에 붙여넣으세요. 날것의 데이터가 해결책을 더 빨리 찾게 해 줌.

이 영상은 6가지의 핵심 효율 팁과 다양한 기능을 어떻게 적절하게 활용하는지 실전 가이드를 제공하여 도움을 줌. [My top 6 tips & ways of using Claude Code efficiently](https://www.youtube.com/watch?v=WwdIYp5fuxY)



# `Claude.md` 실전 템플릿

`CLAUDE.md`는 사람이 읽기 위한 리드미가 아니라, Claude의 뇌에 직접 주입하는 시스템 프롬프트임. 따라서 길고 친절한 문장보다는, 기계가 즉각적으로 이해할 수 있는 명확하고 단호한 규칙 나열이 훨씬 효과적임.

---
## 1. AI를 위한 단답형·선언적 작성

Claude는 이 파일을 매번 읽음. 불필요한 서술어는 토큰만 낭비하므로 제거하자.

* 나쁜 예: "우리 프로젝트에서는 가능하면 탭 대신 스페이스 2칸을 사용해서 들여쓰기를 해주면 좋겠음."
* 좋은 예: "들여쓰기: 스페이스 2칸 (탭 금지)."

## 2. 필수 포함 4대 요소

명확한 지시가 없으면 Claude는 일반적인 웹 표준을 따름. 당신의 프로젝트만의 '예외'나 '규칙'을 명시해야 함.

1. 빌드 및 테스트 명령어: Claude가 코드를 짠 후 스스로 검증할 수 있도록 정확한 스크립트를 적어주세요.
2. 기술 스택 및 버전: 단순히 'React'가 아니라 'React 18, Next.js 14(App Router)'처럼 구체적으로 적어야 옛날 문법을 쓰지 않음.
3. 코드 스타일 컨벤션: 따옴표(단일/이중), 세미콜론 여부, 네이밍 규칙(camelCase vs snake_case) 등.
4. 아키텍처 규칙: "비즈니스 로직은 컴포넌트 밖으로 분리해라", "상태 관리는 Zustand만 쓴다" 같은 구조적 합의 사항.

## 3. '오답 노트'로 활용하기 (가장 중요)

처음부터 완벽한 `CLAUDE.md`를 짤 필요는 없음. Claude Code와 작업하다가 Claude가 당신의 코딩 스타일을 무시하거나, 반복해서 틀리는 부분이 생기면 바로 그 내용을 `CLAUDE.md`에 한 줄씩 추가하자.
예: `* 주의: 데이터베이스 접근 시 절대 직접 쿼리하지 말고 Drizzle ORM을 사용할 것.`

## 4. 복붙해서 쓰는 실전 템플릿

아래 템플릿을 복사하여 프로젝트 성격에 맞게 괄호 안의 내용만 수정해서 바로 사용해 보세요.

```markdown
# Project Overview
이 프로젝트는 (서비스 목적/이름)을 위한 (프론트엔드/백엔드) 레포지토리임.

# Tech Stack
* Language: TypeScript 5.x
* Framework: Next.js 14 (App Router 전용, Pages Router 사용 금지)
* Styling: Tailwind CSS
* State Management: Zustand

# Commands
* 개발 서버 실행: `npm run dev`
* 타입 검사: `npm run type-check`
* 린트 검사: `npm run lint`
* 테스트 실행: `npm run test` (코드 수정 후 반드시 실행하여 통과 여부 확인할 것)

# Code Style & Conventions
* 들여쓰기: 스페이스 2칸
* 문자열: 작은따옴표(') 사용
* 파일명: 컴포넌트는 PascalCase (예: `Button.tsx`), 유틸 함수는 camelCase (예: `formatDate.ts`)
* 세미콜론: 항상 사용
* 타입 선언: `interface` 대신 `type` alias 사용을 권장함

# Architecture Rules
* 모든 UI 컴포넌트는 `src/components` 내부에 작성.
* API 호출 로직은 화면 컴포넌트에 직접 작성하지 말고 `src/services`로 분리할 것.
* 컴포넌트 작성 시 항상 React.FC 대신 일반 함수형 선언(`function Component() {}`)을 사용할 것.
```
