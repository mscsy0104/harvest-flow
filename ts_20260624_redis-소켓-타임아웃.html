TS_20260624_Redis-소켓-타임아웃

TS_20260624_Redis-소켓-타임아웃

Aug 01, 20264 min read

🤖 AI 자동 요약 및 인덱싱

요약:

  • Redis 큐 작업 중 발생하는 소켓 타임아웃 오류는 장시간 유휴 상태의 TCP 연결이 방화벽/NAT에 의해 강제 종료되면서 발생한다.
  • 해결을 위해 socket_keepalive를 적용하여 연결을 유지하고, blpop 호출 시 제한된 타임아웃 값을 지정해 주기적인 연결 갱신 주기를 확보해야 한다.

태그: redis 소켓통신 블로킹

본문

Redis 소켓 타임아웃 장애 분석 및 해결

문제

  • type01_processor 실행 중 CLI에 RedisGetException traceback 출력
  • 오류 메시지: Redis 큐 추출 실패 - Timeout reading from socket
  • 호출 스택: processor.run() → get_queue_task() → dequeue(True) → blpop()

원인 분석

조사 명령어

코드 상 문제 지점

  • redis_client.py:32: StrictRedis(encoding="utf-8", decode_responses=True) — host/port/timeout 미지정, socket_keepalive 미설정
  • redis_client.py:262: blpop(self.__queue_key, timeout=None) — timeout=None 시 무한 블로킹

원인

  • blpop(timeout=None) 으로 인해 큐가 빌 때 TCP 연결이 무한 idle 상태 유지
  • 방화벽/NAT이 idle TCP 세션을 일정 시간(통상 5~30분) 후 강제 종료
  • Redis 클라이언트는 연결이 끊겼음을 모른 채 블로킹 대기 → Timeout reading from socket 발생
  • 큐에 작업이 없는 시간이 길어질수록 재현 빈도 증가

해결

1. socket_keepalive=True 추가 (redis_client.py:32)

  • TCP keepalive 패킷을 주기적으로 전송해 NAT/방화벽이 세션을 유지하도록 함

2. blpop timeout 유한값 지정 (redis_client.py:264)

  • 30초마다 블로킹 해제 후 재시도 → 연결 갱신 주기 확보
  • None 반환 시 caller가 루프 계속 처리 필요

해결법의 장단점 및 잠재적 위험성

socket_keepalive=True

구분내용
장점코드 변경 최소, 연결 안정성 향상
단점OS 레벨 keepalive 간격(기본 2시간)이 NAT timeout보다 길 수 있음
위험socket_keepalive_options로 간격 조정 안 하면 효과 없을 수 있음. Redis 서버가 keepalive를 무시하는 설정이면 무의미

blpop(timeout=30)

구분내용
장점연결 끊겨도 30초 내 자동 복구. 근본적 해결
단점None 반환 처리 필요 — caller iter(lambda: dequeue(True), None) 패턴이 None 반환 시 이터레이터 종료됨
위험caller 수정 없이 배포 시 큐가 비면 processor 루프 종료될 수 있음. sentinel=None 조건과 충돌

권장 대응

  • socket_keepalive=True + socket_keepalive_options 설정 (OS keepalive 간격 단축)
  • blpop(timeout=30) 적용 + caller에서 None 반환 시 continue 처리로 루프 유지
  • 두 방법 병행 적용이 가장 안전
